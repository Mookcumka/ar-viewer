## На iPhone

1. Открыть тестовый адрес **в Safari**, дождаться офлайн-готовности, нажать «Открыть камеру» и разрешить камеру.
2. Считать QR листа прямо внутри этой страницы. Системная камера iPhone и QR из A/B ведут на прежний production-адрес: для нового теста не открывать его заново через системную камеру.
3. Перед заменой PDF нажать «Новый лист», затем считать новый QR. Для AR5 собрать все части; счётчик покажет недостающие. Старая геометрия скрывается.
4. «Поставить заново» сохраняет данные и повторно находит позу Hiro. «Пауза» останавливает камеру; возобновление без перезагрузки страницы.
5. «Отчёт» сохраняет локальный JSON. Для анализа прислать его и запись экрана с моментом проблемы. Кадры камеры в журнал не записываются, автоматической отправки нет.

Safari продолжает отслеживать Hiro и скрывает модель при его потере. Это **не ARKit world anchoring**; качество и устойчивость на физическом iPhone требуют проверки владельцем. Сравнительное ARKit-приложение — отдельный Xcode-проект, не запускается в Safari.

Для одинакового теста A/B линейкой выставить контрольную линию100мм; полный QR с белым полем40мм, чёрная рамка Hiro40мм, центры80мм. На мониторе PDF100% не гарантирует миллиметры. Экран и zoom не менять. Native знает только A/B; обычные AR4/AR5 поддерживает браузерная часть.
