# Exporto → бинарные QR → Safari → AR Quick Look

26.10.2026. Решение владельца: разрешена разовая загрузка **кода** открытого просмотрщика по заменяемому HTTPS и встроенный Quick Look без установки своего приложения. Геометрия остаётся в QR. Исходная строгая гипотеза первого запуска полностью офлайн на неподготовленном iPhone не подтверждена. Кэш может быть удалён iOS. Ни исчезновение URL, ни первый офлайн-запуск этим решением не устранены.

Связь: Exporto #16/#33, AR #32/#21, Exporto Draft #71. Нативные PR #67/#71 сохранены; этот браузерный путь не зависит от их слияния. База AR main `6d8a5e8db02a466ec85b6bbfe8df7a677ab2121b`. Совместимость проверяется с Exporto `6e2e11fa8d76f3505c340da73f92878a47aa55ad`; его экспортёр, UI, генераторы и установщик этим PR не меняются. Нового формата геометрии нет.

## Цепочка и ограничения

1. Штатная Camera iPhone считывает **отдельный QR HTTPS-запуска**. Он содержит только адрес открытого просмотрщика. Старый способ `data:text/html` не прошёл физический тест 20.10 ([Exporto #16](https://github.com/Mookcumka/MyRevitPluginNet8/issues/16#issuecomment-6289233384)). Бинарный QRL1 не объявляется запускающей ссылкой.
2. В Safari пользователь нажимает «Сканировать QR», разрешает камеру и последовательно считывает части Exporto в любом порядке. Используется **jsQR.binaryData**, без преобразования бинарных пакетов в UTF-8. Дубликаты разрешены; смешение моделей/конфликт/неполный набор отвергаются. Для смены модели есть «Новый лист»: прежний Blob URL отзывается, камера и асинхронные операции отменяются.
3. Текущий QRL1: magic4 + SHA25632 + total UInt32LE + index/count UInt16LE + length UInt32LE + body. 1/3/6 частей; body≤857, scene≤5142 bytes; заголовок48. SHA относится ко **всему gzip**. После проверки — ограниченная распаковка32MiB и CBX1 с metadata≤2MiB. Profile Exporto-AR-experimental-1,16bits/metres/Y-up, последовательные mesh offsets, только уже baked identity nodes. `originMeters` и export scale не применяются второй раз. Bounds/RGBA/indices/размеры проверяются до USDZ.
4. USDZ создаётся в браузере из восстановленных треугольников. Общий `ar-poc/usdz.js` переиспользуется, а не заменяется вторым writer. Опциональные linearColor/opacity/precisePositions сохраняют прежний legacy output; новый путь использует точное sRGB→linear, alpha и проверенную float32-геометрию. Если преобразование схлопывает треугольник/меняет нормаль — явный отказ. Строковые имена/инструкции из HTML в сцену не исполняются. Нет кубов, album-ID dispatch или загрузки модели с сервера в runtime.
5. Пользователь нажимает настоящую ссылку `rel=ar` с единственным дочерним img и Blob MIME `model/vnd.usdz+zip`. Quick Look — встроенный в iOS AR, отдельное приложение не устанавливается. Если сначала открылся объектный просмотр, выбрать вкладку **AR**, найти поверхность и разместить модель. Это **не автоматическая привязка к чертежу** и не прежний native world-anchor. Масштаб уже задан Exporto; Quick Look также допускает действия пользователя с масштабом/положением. Для сравнения фиксировать фактически отображённые размеры и взаимодействия.

Дополнительный предел браузерного USDZ —50000 треугольников и32MiB готового файла. При превышении нет скрытого LOD/обрезки/облака. Это safety limit прототипа, не новый QR-бюджет. UV/изображения/PBR/исходные normals/BIM/camera/light/placement исключаются уже экспортёром и отображаются пользователю по его отчёту. Flat normals вычисляются из треугольников. Поддержка alpha в реальном Quick Look остаётся устройственной проверкой.

Обычный 3D или скачивание USDZ не являются доказательством AR. `relList.supports('ar')` — только capability hint. Отчёт регистрирует нажатие, но никогда не объявляет Quick Look/AR успешным автоматически. Haptics, WebXR, маркеры, baking/LOD и native tracking этим этапом не изменяются.

Основания: [Apple Camera QR](https://support.apple.com/en-us/102680), [Apple WWDC19: Blob URL и rel=ar](https://developer.apple.com/videos/play/wwdc2019/612/), [WWDC26: inline model и Quick Look AR](https://developer.apple.com/videos/play/wwdc2026/215/), [WebKit gzip API с Safari16.4](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/), [политика удаления кэша](https://webkit.org/blog/14403/updates-to-storage-policy/). Документация API не заменяет тест конкретной iOS27.2 владельца.

## Распространение и автономность

Отдельная страница `ar-poc/qr-sheet/index.html`; legacy root viewer не перенаправляется и его tracking не меняется. Внешние CDN и runtime-зависимость от автора отсутствуют. Используется прежний jsQR1.4.0 (vendor blob429896a9d087eb3977cf67521f738d01af17c808), лицензия Apache-2.0 включена из upstream LICENSE blob8f71f43fee3f78649d238238cbde51e6d7055c82; upstream package.json blob1724343d84f6354bbf9e6ccbea82402a79c13d80 подтверждает1.4.0/Apache-2.0. Нужен любой HTTPS-хост статического кода. Это заменяемая инфраструктура для первоначальной загрузки, а не хранилище геометрии.

`python3 ar-poc/qr-sheet/package.py /tmp/Exporto-Safari-QR-viewer.zip` собирает 8 runtime-файлов, переносимую инструкцию, jsQR Apache-2.0 license/notice, README и SHA-манифест. **Не включает test/**, fixtures, модели, плагины или generated scene data. Сохраняет иерархию `qr-sheet/`, `usdz.js`, `vendor/jsQR.js`; точка входа `qr-sheet/index.html`. Публикацию не выполняет. Опционально `--viewer-url https://HOST/PATH/qr-sheet/index.html` добавит `launch.svg` с этим адресом; для этой build-time операции нужен существующий reportlab. Геометрия в URL не добавляется. Готовый архив переносится на иной хост без перекодирования QR геометрии, но старый напечатанный QR запуска сам по себе адрес не изменит: альтернативный просмотрщик нужно открыть вручную/по новому QR.

Изолированный child Service Worker кэширует только allowlist кода/assets. Готовность проверяется у **своей активированной регистрации** с scope/version; чужой parent ready не принимается. Чужие кэши не удаляются. Старый builder из родительского кэша даёт понятный отказ до модели; после загрузки новой child-копии нужно обновить страницу. Никакие камера/пакеты/модели/HTML не сохраняются в Cache API. На скрытие страницы camera tracks останавливаются; при возврате Quick Look готовый Blob остаётся доступным.

HTML-file import — запасная диагностика: текст читается как данные, извлекаются только `data-packet` без DOM/script/URL evaluation. Он подтверждает восстановление, **не оптическое чтение QR**. QR camera mode работает без сохранения кадра/геометрии на сервер; CSP допускает только собственный код и Blob, нет analytics.

## Проверки и статус

Node: `node --test ar-poc/qr-sheet/test/codec.test.cjs ar-poc/test/qr.test.cjs`. Байты C# vectors перенесены без изменения в numeric byte arrays (без base64-строк в tracked JSON) из Exporto PR71 `tools/ar-sheet-verify/vectors.json` (blob `98b10acc6087fe7bdb73730f7a1722a8f3e7407f`). Их source явно обозначен: SceneData/SceneBuilders, **не запуск Revit**. Эти fixtures разрешены только в тестах. Проверяются все1/3/6 части, SHA, размеры, цвет/opacity, нормализация, float32/вырождение, отказы malformed, ZIP CRC/alignment и побайтная сохранность legacy USDA. Новый Node-набор подключён к существующему CI; runner/деплой-процесс не меняется.

Локальные браузерные проверки (Playwright, без iPhone): `python3 ar-poc/qr-sheet/test/make_camera_fixture.py /tmp/exporto-safari-qr-test`, затем `TEST_OUTPUT=/tmp/exporto-safari-qr-test node ar-poc/qr-sheet/test/browser-smoke.cjs` с установленным тестовым Chromium/Playwright. Reportlab/Pillow нужны только генератору fake-camera теста, не runtime/Node CI. Проверяются1/6-part HTML, untrusted HTML, отзыв Blob, отмена медленного импорта, child/parent stale-cache, офлайн-повтор, 6частей binary QR через fake-camera/jsQR, остановка/продолжение камеры, rel=ar UI contract (с mock capability, без настоящего Quick Look), отсутствие внешних запросов, мобильная ширина и честные acceptance flags. **Не выдавать этот набор за тест штатной камеры iPhone или настоящий Quick Look.**

Результат локального прогона: **23/23 Node**, все десять browser gates выше пройдены, включая fake-camera6/6 и stale-parent-cache. Ширина393px проверена снимком. Это software evidence, не физический тест.

## Практический первый тест — после отдельного согласования публикации

1. Владелец самостоятельно использует уже подготовленный EXE Exporto PR71 в Revit2027. Агент не устанавливает, не запускает Revit/Parallels и не меняет настройки. Работать с копией проекта и сохранить штатную рабочую сборку/возможность её переустановить по прежнему процессу.
2. Источник — настоящие стены с проёмами AR-T.07 существующего «Тест AR». Подтвердить семь настоящих ElementId и владение по существующим album/Role artest правилам; использовать поддерживаемый3D-вид и именно эти элементы, без стен AR-T.05/06 и прочей модели. Не выбирать только по имени/дальним координатам. Не использовать параметрический куб AR-T.03 как доказательство SceneData. Генератор не копировать/менять.
3. Экспортировать **новый формат «AR-лист (QR)»**. Сохранить новый HTML и отчёт Exporto. Если отказ по ёмкости — сохранить фактические размеры; не менять сцену/алгоритм скрытно. Старые AR4/AR5 QR на листе Test AR — другой формат: для этого испытания сканировать именно **новые QR в HTML Exporto**.
4. На Mac/экране открыть QR запуска проверенного HTTPS-просмотрщика. На iPhone15Pro/iOS27.2: стандартная **Camera → ссылка → Safari**. Дождаться сообщения о готовности офлайн-копии; затем «Сканировать QR», разрешить камеру и считать части нового HTML Exporto. Добиться N/N, SHA-256 OK и ожидаемых габаритов/проёмов.
5. «Открыть модель в AR» → при необходимости вкладка AR → найти поверхность, разместить модель, обойти её камерой. Неподготовленный полностью офлайн первый запуск не проверять как уже поддержанный.

До финальной приёмки **ещё одна реальная модель Revit вне альбомов**, без правки алгоритма. Подтвердить все источники; тестовые Node fixtures не заменяют эти шаги.
