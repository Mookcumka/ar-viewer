# Проверка укрепления QR-прототипа — 20.10.2026

База: `feature/ar-qr-cube-poc@93bcf417eac07929aaacc96f1b1d7fd51cdf3bfa`.
Изменения относятся к воспроизводимости эксперимента с кубом. Реальная геометрия,
совмещение с планом и публикация сайта в этот этап не входят.

## Проверено

- Node.js: 8/8 регрессионных проверок. Протокол, неверные значения, отсутствие
  AR-сцены при неверном QR, система AR.js, размер куба, кэш и позднее разрешение камеры.
- XML проекта и YAML workflow успешно разобраны; штатный tools/check_profiles.py: ошибок 0, предупреждений 0.
- Release-сборка прошла на Linux с .NET SDK 10.0.402 и EnableWindowsTargeting=true:
  ошибок 0, одно предупреждение CS8602 в неизменённом FamilyCatalog.cs:197.
  QRCoder.dll присутствует в выходной папке; Hiro встроен в AR.Style.dll.
- Chromium 154 + Playwright, локальный HTTP на loopback (secure context): неверный
  QR не создаёт сцену и не запрашивает камеру; все ресурсы попадают в офлайн-кэш;
  при отключённой сети просмотрщик создаёт куб с размером 1 единица маркера,
  имитированная камера запускается и в просмотрщике, и в сканере.
- В браузерном сценарии нет pageerror и запросов к внешним хостам.
- Проверка реального AR.js выявила регистрацию через `AFRAME.systems.arjs`;
  проверка повторной ссылки выявила необходимость reload при `hashchange`.
  Обе проблемы исправлены.
- Независимый агент ChatGPT повторно проверил код и самостоятельно выполнил
  Node-проверки (8/8). Новых блокирующих замечаний не сообщил. Это не ревью Claude.

## Воспроизведение

`node ar-poc/test/qr.test.cjs`

Дополнительный браузерный сценарий: Python + Playwright + Chromium,
`python ar-poc/test/browser_smoke.py`. Можно задать `CHROMIUM_PATH` или установить
браузер Playwright. Сценарий запускает локальный сервер и использует имитированную
камеру; это не проверка распознавания реального Hiro. В CI включены Node-проверки;
браузерный сценарий остаётся отдельным запуском.

## Не подтверждено

Сборка на Linux не подтверждает поведение Revit API или Windows-установщика.
Revit 2027, фактическая поставка DLL на чистой Windows, поведение транзакции и
Extensible Storage, размер PDF/печати, реальное отслеживание Hiro, Safari/PWA и
офлайн-камера iPhone требуют проверок из [чеклиста](README.md).

## Сохранённые upstream-изменения

Коммит `93bcf41` добавил `CopyLocalLockFileAssemblies`, x64 и Debug-развёртывание.
Они сохранены. Дополнительно исправлены ZIP/EXE, локальный Hiro и его калибровка,
повторное размещение, проверка фиксации транзакции, валидация QR, работа с камерой
и изоляция кэша. Прежняя QR-ветка и main этим PR автоматически не сливаются.
